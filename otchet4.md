# Лабораторная работа №4. Мониторинг Docker-контейнеров с помощью Grafana и Prometheus (Аминов А.А. ИВТ-ИСУ-302Б)

## Что изменилось по сравнению с третьей лабой?

В третьей лабораторной работе мы создали клиент-серверное приложение. В четвертой работе мы не трогали само приложение, а развернули для него **полноценный стек мониторинга**. Теперь мы можем в реальном времени видеть, сколько ресурсов (процессор, память, сеть) потребляет наш сайт и база данных, и наглядно визуализировать эти данные на графиках.

## Архитектура мониторинга

Мы развернули систему из 4 контейнеров, которые работают в одной сети Docker:
1. **webapp (nginx)** — тестовое приложение (наш веб-сервер).
2. **cAdvisor** — агент, который собирает метрики со всех контейнеров (использует cgroups).
3. **Prometheus** — база данных временных рядов, которая периодически опрашивает cAdvisor и хранит историю метрик.
4. **Grafana** — платформа визуализации, которая берет данные из Prometheus и рисует красивые графики.

**Схема работы:**
`webapp` ➔ `cAdvisor (собирает)` ➔ `Prometheus (хранит)` ➔ `Grafana (рисует)`

## Инструкция по запуску

### 1. Подготовка конфигурационных файлов
В папке проекта созданы два файла:
- `docker-compose.yml` — описывает сервисы, сети и порты.
- `prometheus.yml` — говорит Prometheus, откуда брать данные (из `cadvisor:8080`).

### 2. Запуск стека
В терминале (в папке, где лежит `docker-compose.yml`) выполняется команда:
```bash
docker compose up -d
```
Docker скачивает образы и запускает контейнеры в фоновом режиме.

### 3. Проверка работы
Команда `docker ps` показывает 4 запущенных контейнера (`webapp`, `cadvisor`, `prometheus`, `grafana`).

## Основные компоненты и их проверка

### 1. cAdvisor (Сборщик метрик)
- **URL:** `http://localhost:8080`
- **Проверка:** Открываем страницу, видим список всех запущенных контейнеров. cAdvisor собирает данные о CPU, RAM, сетевом трафике и диск I/O.

### 2. Prometheus (База данных и обработка)
- **URL:** `http://localhost:9090`
- **Проверка:** Переходим в **Status → Targets**. Убеждаемся, что target `cadvisor` имеет статус **UP**.
- **Тестовый запрос:** Вводим `container_cpu_usage_seconds_total` и нажимаем Execute. Видим таблицу с метриками (время, контейнер, значение).

### 3. Grafana (Визуализация)
- **URL:** `http://localhost:3000` (логин/пароль: `admin`/`admin`)
- **Подключение источника:** В `Configuration → Data Sources` добавляем Prometheus с URL `http://prometheus:9090` (обязательно имя контейнера, а не localhost). Жмем **Save & test** — должно появиться "Data source is working".

## Создание дашборда и проверка нагрузки

1. В Grafana создаем новый Dashboard → Add visualization.
2. Выбираем Prometheus, переключаем режим на **Code** (чтобы писать запросы вручную).
3. Вводим PromQL запрос:
   ```promql
   rate(container_cpu_usage_seconds_total{name="webapp"}[5m])
   ```
4. Устанавливаем время "Last 5 minutes" и нажимаем **Run queries**.

**Генерация нагрузки:**
Чтобы проверить, что мониторинг работает в реальном времени, мы отправляем 1000 HTTP-запросов к нашему `webapp`:
```bash
for i in {1..1000}; do curl -s http://localhost > /dev/null; done
```
*(В Windows PowerShell используется команда `1..1000 | ForEach-Object { Invoke-WebRequest -Uri http://localhost -UseBasicParsing | Out-Null }`)*

**Результат:** На графике в Grafana видно, как в момент нагрузки линия использования CPU резко уходит вверх. После завершения запросов метрика возвращается к нулю.
