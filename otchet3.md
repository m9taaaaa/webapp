# Лабораторная работа №3. Backend с REST API и базой данных (Аминов А.А. ИВТ-ИСУ-302Б)

## Что изменилось по сравнению со второй лабой?

Во второй лабораторной работе наше приложение было полностью клиентским. Все данные (карточки комплектующих) хранились в памяти браузера (localStorage). Если мы открывали сайт с другого компьютера или очищали кэш, товары исчезали.

В третьей лабораторной мы разделили проект на две части: **Frontend** (сайт) и **Backend** (сервер). Теперь данные хранятся в настоящей базе данных на сервере, а сайт обращается к ним через HTTP-запросы (REST API).

## Выбранная тема и сущность

- **Тема проекта:** Каталог компьютерных комплектующих (PC Parts).
- **Основная сущность:** Комплектующее (`Component`).

**Поля сущности:**
- `id` — уникальный идентификатор (целое число).
- `name` — название комплектующего (строка).
- `category` — категория (процессор, видеокарта, материнская плата, ОЗУ).
- `vendor` — производитель (AMD, Intel, NVIDIA и т.д.).
- `price` — цена в рублях (целое число).
- `description` — краткое описание.
- `image` — ссылка на изображение.
- `specs` — характеристики (сохраняются в виде JSON-строки).

## Используемый стек
- **Backend:** Python, FastAPI.
- **База данных:** SQLite (реляционная, создается в файле `test.db`).
- **ORM:** SQLAlchemy (для работы с БД из Python).
- **Валидация:** Pydantic.
- **Frontend:** HTML, CSS, JavaScript (Vanilla JS).
- **Документация API:** Swagger UI (генерируется автоматически).

## Реализованные endpoint-ы (CRUD)

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/components` | Получить список всех комплектующих |
| `POST` | `/api/components` | Создать новую запись |
| `GET` | `/api/components/{id}` | Получить одну запись по ID |
| `PATCH` | `/api/components/{id}` | Частично обновить запись |
| `DELETE` | `/api/components/{id}` | Удалить запись |

*(Все методы возвращают правильные HTTP-статусы: 200 OK, 201 Created, 204 No Content, 404 Not Found, 422 Unprocessable Content).*

## Как устроен код (по-простому)

### 1. База данных (SQLite)
Данные хранятся в файле `test.db`, который создается автоматически при первом запуске сервера. За работу с базой отвечает файл `database.py` и модели в `models.py`. Мы описали таблицу `components` с нужными колонками и типами данных.

### 2. Валидация (Pydantic)
Файл `schemas.py` содержит «правила» для данных. Сервер не примет данные от пользователя, если они не соответствуют этим правилам. Например, если попытаться отправить товар без названия или с ценой в виде текста, сервер вернет ошибку 422 и не запишет это в базу.

### 3. API (FastAPI)
В файле `main.py` описаны все маршруты (endpoints). Когда сайт отправляет запрос, FastAPI вызывает нужную функцию, которая читает или записывает данные в базу через SQLAlchemy. При первом запуске в базу автоматически загружаются 24 стартовых комплектующих.

### 4. Фронтенд
Файл `app.js` больше не использует `localStorage`. Теперь при загрузке страницы он делает `fetch` (GET) запрос к серверу, получает список товаров и рисует карточки. При нажатии «Добавить» отправляет POST-запрос, а при удалении — DELETE.
